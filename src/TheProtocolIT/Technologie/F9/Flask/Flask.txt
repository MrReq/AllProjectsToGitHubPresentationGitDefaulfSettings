# Flask

## Czym jest Flask?

Flask to lekki i elastyczny framework webowy napisany w języku **Python**.

Służy przede wszystkim do tworzenia:

aplikacji internetowych.

REST API.

backendów.

mikroserwisów.

prototypów.

aplikacji wykorzystujących bazy danych.

Flask jest określany jako **microframework**, ponieważ sam w sobie dostarcza stosunkowo niewiele funkcji i pozwala programiście samodzielnie dobierać dodatkowe biblioteki.

## Do czego służy Flask?

Flask można wykorzystać do tworzenia:

stron internetowych.

REST API.

backendów aplikacji frontendowych.

mikroserwisów.

aplikacji mobilnych posiadających backend.

paneli administracyjnych.

aplikacji wykorzystujących bazy danych.

prototypów i MVP.

aplikacji AI i Machine Learning.

## Flask a Python

Flask jest frameworkiem dla języka Python.

Najprostsza aplikacja Flask może wyglądać tak:

```python
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello World!"

if __name__ == "__main__":
    app.run()
```

Po uruchomieniu aplikacja będzie dostępna zazwyczaj pod:

```text
http://127.0.0.1:5000
```

## Instalacja Flask

Flask można zainstalować za pomocą `pip`:

```bash
pip install flask
```

Można sprawdzić instalację:

```bash
flask --version
```

Jeżeli plik nazywa się:

```text
app.py
```


## Route

**Route** określa adres URL obsługiwany przez aplikację.

Przykład:

```python
@app.route("/users")
def users():
    return "Users"
```

Po wejściu na:

```text
/users
```

wywołana zostanie funkcja `users()`.

## HTTP Methods

Flask pozwala określić, jakie metody HTTP może obsługiwać dany endpoint.

Domyślnie `route()` obsługuje `GET`.

Możemy określić inne metody:

```python
@app.route("/users", methods=["POST"])
def create_user():
    return "User created"
```

Możemy również obsługiwać kilka metod:

```python
@app.route("/users", methods=["GET", "POST"])
def users():
    pass
```

Najczęściej wykorzystywane metody to:

`GET` – pobieranie danych.

`POST` – tworzenie danych.

`PUT` – pełna aktualizacja danych.

`PATCH` – częściowa aktualizacja danych.

`DELETE` – usuwanie danych.

## Parametry URL

Flask umożliwia definiowanie parametrów bezpośrednio w ścieżce.

```python
@app.route("/users/<int:user_id>")
def get_user(user_id):
    return f"User ID: {user_id}"
```

Dla:

```text
/users/15
```

Flask przekaże do funkcji:

```python
user_id = 15
```

Możemy określać również typ parametru.

Przykładowo:

```python
<int:user_id>
<string:name>
<float:price>
<path:file_path>
<uuid:user_id>
```

## Query Parameters

Flask pozwala odczytywać parametry znajdujące się po `?`.

Przykład:

```text
/users?name=Jan
```

Kod:

```python
from flask import request

@app.route("/users")
def users():
    name = request.args.get("name")

    return {
        "name": name
    }
```

`request.args` zawiera parametry query string.

## JSON

Flask może obsługiwać dane JSON przesyłane przez klienta.

Przykład:

```python
from flask import request

@app.route("/users", methods=["POST"])
def create_user():
    data = request.get_json()

    return {
        "name": data["name"]
    }
```

Klient może wysłać:

```json
{
    "name": "Jan",
    "age": 25
}
```

## JSON Response

Flask umożliwia zwracanie danych jako JSON.

Przykład:

```python
@app.route("/api/users")
def users():
    return {
        "id": 1,
        "name": "Jan"
    }
```

Flask automatycznie przekształci taki słownik na odpowiedź JSON.

Możemy również wykorzystać `jsonify()`:

```python
from flask import jsonify

@app.route("/api/users")
def users():
    return jsonify({
        "id": 1,
        "name": "Jan"
    })
```

## Status Codes

Możemy zwracać określone kody HTTP.

Przykład:

```python
@app.route("/users", methods=["POST"])
def create_user():
    return {
        "message": "Created"
    }, 201
```

Najczęściej wykorzystywane kody to:

`200 OK` – sukces.

`201 Created` – utworzono zasób.

`204 No Content` – sukces bez treści.

`400 Bad Request` – nieprawidłowe żądanie.

`401 Unauthorized` – brak uwierzytelnienia.

`403 Forbidden` – brak uprawnień.

`404 Not Found` – zasób nie istnieje.

`409 Conflict` – konflikt danych.

`500 Internal Server Error` – błąd serwera.

## Response

Możemy mieć pełną kontrolę nad odpowiedzią HTTP.

Przykład:

```python
from flask import Response

@app.route("/hello")
def hello():
    return Response(
        "Hello",
        status=200,
        mimetype="text/plain"
    )
```

Możemy ustawiać:

status HTTP.

nagłówki.

typ MIME.

treść odpowiedzi.

## Templates

Flask może również generować strony HTML.

Do tego wykorzystuje przede wszystkim silnik szablonów **Jinja**.

Przykład:

```python
from flask import render_template

@app.route("/")
def home():
    return render_template(
        "index.html",
        name="Jan"
    )
```

Struktura projektu:

```text
project/
├── app.py
└── templates/
    └── index.html
```

W pliku HTML możemy użyć:

```html
<h1>Hello {{ name }}</h1>
```

Rezultat:

```text
Hello Jan
```

## Jinja

**Jinja** to silnik szablonów wykorzystywany przez Flask.

Pozwala między innymi:

wyświetlać zmienne.

wykonywać instrukcje warunkowe.

wykonywać pętle.

dziedziczyć szablony.

tworzyć reusable components.

Przykład:

```html
{% if user %}
    <h1>Hello {{ user.name }}</h1>
{% else %}
    <h1>Hello Guest</h1>
{% endif %}
```

## Sessions

Flask posiada mechanizm **sessions**.

Session pozwala przechowywać informacje związane z użytkownikiem pomiędzy kolejnymi żądaniami.

Przykład:

```python
from flask import session

app.secret_key = "secret-key"

@app.route("/login")
def login():
    session["user_id"] = 123

    return "Logged in"
```

Później:

```python
user_id = session.get("user_id")
```

W praktycznej aplikacji sekret powinien być przechowywany bezpiecznie, na przykład w zmiennej środowiskowej, a nie bezpośrednio w kodzie.

## Cookies

Flask umożliwia również pracę z cookies.

Możemy ustawić cookie:

```python
from flask import make_response

@app.route("/")
def index():
    response = make_response("Hello")
    response.set_cookie("username", "Jan")

    return response
```

Możemy je następnie odczytać:

```python
from flask import request

username = request.cookies.get("username")
```

## Blueprints

W większych projektach nie powinno się umieszczać wszystkich endpointów w jednym pliku.

Flask posiada mechanizm **Blueprints**.

Blueprint pozwala podzielić aplikację na logiczne moduły.

Przykładowo:

```text
app/
├── __init__.py
├── users/
│   └── routes.py
├── auth/
│   └── routes.py
└── products/
    └── routes.py
```

Możemy mieć osobny Blueprint dla:

Users.

Authentication.

Products.

Orders.

Payments.

## Przykład Blueprint

```python
from flask import Blueprint

users_bp = Blueprint(
    "users",
    __name__,
    url_prefix="/users"
)

@users_bp.route("/")
def get_users():
    return []
```

Następnie rejestrujemy go w aplikacji:

```python
app.register_blueprint(users_bp)
```

Dzięki temu aplikacja jest bardziej modularna.

Można więc rozszerzyć Flask zgodnie z potrzebami projektu.

## Flask-SQLAlchemy

Flask-SQLAlchemy ułatwia wykorzystanie SQLAlchemy w aplikacji Flask.

Przykładowy model:

```python
from flask_sqlalchemy import SQLAlchemy

db = SQLAlchemy()

class User(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    name = db.Column(db.String(100))
    email = db.Column(db.String(255))
```

Model może reprezentować tabelę w bazie danych.

## Middleware i WSGI

Flask jest frameworkiem opartym na standardzie **WSGI – Web Server Gateway Interface**.

WSGI definiuje sposób komunikacji pomiędzy aplikacją Python a serwerem webowym.

Schemat:

```text
Client
  ↓
Web Server
  ↓
WSGI
  ↓
Flask
  ↓
Application
```

Popularnym serwerem WSGI dla aplikacji Flask jest **Gunicorn**.

## Flask a ASGI

Flask tradycyjnie opiera się na WSGI.

Nowoczesne frameworki takie jak FastAPI są projektowane przede wszystkim z myślą o **ASGI**.

Można to zapamiętać:

```text
Flask
→ WSGI

FastAPI
→ ASGI
```

ASGI lepiej odpowiada potrzebom aplikacji wykorzystujących intensywnie programowanie asynchroniczne i WebSockety.

## Flask i WebSocket

Flask sam w sobie nie jest nastawiony na WebSockety.

Można jednak wykorzystać rozszerzenia, takie jak **Flask-SocketIO**.

## Flask vs FastAPI

Flask i FastAPI są frameworkami Pythona do tworzenia backendów i API.

**Flask** jest minimalistyczny i bardzo elastyczny.

**FastAPI** jest bardziej nastawione na nowoczesne API, type hints, automatyczną walidację i programowanie asynchroniczne.

Flask tradycyjnie wykorzystuje WSGI.

FastAPI wykorzystuje ASGI.

Flask posiada ogromny i dojrzały ekosystem.

FastAPI automatycznie generuje dokumentację OpenAPI.

Można to uprościć:

```text
Flask
→ prosty, elastyczny, minimalistyczny

FastAPI
→ API, async, type hints, automatyczna dokumentacja
```

## Flask vs Django

Flask jest mikroframeworkiem.

Django jest rozbudowanym frameworkiem typu **batteries included**.

Flask daje programiście większą swobodę w wyborze komponentów.

Django posiada wiele funkcji dostępnych od razu.

Można to zapamiętać:

```text
Flask
→ wybierasz potrzebne komponenty

Django
→ wiele komponentów dostajesz od razu
```

## Wady Flask

Sam Flask dostarcza stosunkowo niewiele funkcji.

Wiele funkcji wymaga dodatkowych bibliotek.

Programista musi samodzielnie zdecydować o architekturze większej aplikacji.

## Flask – najważniejsze do zapamiętania

Flask jest lekkim frameworkiem webowym dla Pythona.

Jest określany jako **microframework**.

Służy do tworzenia stron internetowych, backendów i REST API.

`@app.route()` definiuje endpoint.

`request` pozwala odczytywać dane z żądania.

`jsonify()` pozwala tworzyć odpowiedzi JSON.

**SQLAlchemy** może być wykorzystywane do komunikacji z bazami danych.

Flask jest bardzo dobrym wyborem, gdy chcemy mieć **lekki, prosty i elastyczny backend w Pythonie**.

Najprościej zapamiętać:

```text
                    FLASK
                      ↓
               Python Web Framework
                      ↓
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
      Routes        Jinja        REST API
        ↓             ↓             ↓
     Request       HTML          JSON
        │
        ↓
     Services
        ↓
    SQLAlchemy
        ↓
    PostgreSQL
```

**Flask = minimalistyczny i elastyczny framework webowy Pythona, który daje Ci podstawy backendu, a resztę komponentów dobierasz według potrzeb.**
