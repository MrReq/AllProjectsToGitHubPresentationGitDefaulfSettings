# Firebase

## Czym jest Firebase?

Firebase to platforma chmurowa firmy Google przeznaczona do tworzenia, rozwijania i utrzymywania aplikacji webowych oraz mobilnych.

Firebase dostarcza gotowe usługi backendowe, dzięki czemu programista nie musi samodzielnie tworzyć całej infrastruktury serwerowej.

Firebase jest często określany jako **Backend as a Service (BaaS)**.

Można dzięki niemu szybko stworzyć aplikację posiadającą między innymi:

logowanie użytkowników.

bazę danych.

przechowywanie plików.

powiadomienia push.

hosting.

analitykę.

monitorowanie błędów.

funkcje backendowe.

## Do czego służy Firebase?

Firebase może być wykorzystywany do tworzenia:

aplikacji mobilnych Android.

aplikacji iOS.

aplikacji webowych.

aplikacji SPA.

MVP.

prototypów.

aplikacji czasu rzeczywistego.

gier.

aplikacji wykorzystujących powiadomienia push.

aplikacji wykorzystujących uwierzytelnianie użytkowników.

## Firebase jako Backend as a Service

Tradycyjna aplikacja może wyglądać tak:

```text
Frontend
    ↓
Backend
    ↓
API
    ↓
Database
    ↓
Storage
```

W Firebase wiele elementów backendu jest dostarczanych jako gotowe usługi:

```text
Frontend
    ↓
Firebase
 ┌──┼───────────────┐
 ↓  ↓       ↓       ↓
Auth Database Storage Functions
```

Programista może korzystać z tych usług bez konieczności budowania całego backendu od podstaw.

## Firebase Authentication

**Firebase Authentication** odpowiada za uwierzytelnianie użytkowników.

Pozwala implementować między innymi:

rejestrację.

logowanie.

wylogowanie.

resetowanie hasła.

logowanie przez Google.

logowanie przez Apple.

logowanie przez GitHub.

logowanie przez Facebook.

uwierzytelnianie numerem telefonu.

Możemy dzięki temu stosunkowo łatwo stworzyć system użytkowników.

Przykładowy przepływ:

```text
User
 ↓
Login
 ↓
Firebase Authentication
 ↓
Verification
 ↓
Authenticated User
 ↓
Application
```

Firebase może również generować tokeny używane do potwierdzania tożsamości użytkownika.

## Firestore

**Cloud Firestore** jest jedną z najważniejszych baz danych Firebase.

Jest to **NoSQL document database**.

Dane są organizowane w:

Collections.

Documents.

Fields.

Przykładowa struktura:

```text
users
 ├── user1
 │    ├── name: "Jan"
 │    ├── age: 25
 │    └── email: "jan@example.com"
 │
 └── user2
      ├── name: "Anna"
      ├── age: 28
      └── email: "anna@example.com"
```

Document przypomina obiekt lub rekord.

Collection jest zbiorem dokumentów.

## Realtime Database

Firebase posiada również **Realtime Database**.

Jest to baza danych NoSQL zaprojektowana z myślą o synchronizacji danych w czasie rzeczywistym.

Przykładowo:

```text
User A
   ↓
Firebase Realtime Database
   ↓
User B
```

Jeżeli użytkownik A zmieni dane, użytkownik B może bardzo szybko otrzymać aktualizację.

Jest to szczególnie przydatne w:

czatach.

grach.

aplikacjach współdzielonych.

systemach monitorowania.

aplikacjach czasu rzeczywistego.

## Firestore vs Realtime Database

Obie technologie służą do przechowywania danych, ale mają inne charakterystyki.

**Cloud Firestore** jest bardziej nowoczesną i elastyczną bazą dokumentową.

**Realtime Database** jest prostszą bazą opartą na strukturze JSON i bardzo mocno koncentruje się na synchronizacji danych w czasie rzeczywistym.

Można to zapamiętać:

```text
Firestore
→ nowoczesna baza dokumentowa

Realtime Database
→ prostsza baza JSON + realtime
```

## Firebase i bezpieczeństwo

Firebase posiada system **Security Rules**.

Reguły pozwalają określić, kto może odczytywać lub modyfikować dane.

Przykładowo możemy określić:

```text
Użytkownik może odczytać własny profil.
```

ale:

```text
Użytkownik nie może zmienić profilu innego użytkownika.
```

Security Rules są szczególnie ważne w przypadku Firestore i Storage.

## Firebase Security Rules

Przykładowa reguła może określać dostęp zależny od zalogowanego użytkownika.

Koncepcyjnie:

```text
if user is authenticated
    → allow read
else
    → deny
```

Reguły powinny być projektowane bardzo ostrożnie.

Błędna konfiguracja może spowodować ujawnienie danych.

## Wady Firebase

Firebase jest usługą chmurową i wiąże aplikację z konkretnym dostawcą.

Koszty mogą rosnąć wraz ze skalą aplikacji.

Firestore ma inną charakterystykę niż tradycyjne relacyjne bazy SQL.

Niektóre bardzo skomplikowane operacje backendowe są łatwiejsze do implementacji we własnym backendzie.

Przeniesienie dużej aplikacji Firebase do innej technologii może wymagać dużo pracy.

Trzeba bardzo dobrze zaprojektować Security Rules.

## Firebase a Supabase

Firebase i Supabase są konkurencyjnymi rozwiązaniami typu Backend as a Service.

Firebase jest mocno związany z ekosystemem Google i oferuje między innymi Firestore oraz Realtime Database.

Supabase wykorzystuje przede wszystkim **PostgreSQL**.

Można zapamiętać:

```text
Firebase
→ Google
→ Firestore / Realtime Database
→ bardzo mocny ekosystem mobilny

Supabase
→ PostgreSQL
→ SQL
→ bardziej klasyczne podejście relacyjne
```

## Firebase a AWS

Firebase jest rozwiązaniem bardziej zorientowanym na szybkie tworzenie aplikacji.

AWS jest znacznie większą platformą chmurową oferującą ogromną liczbę usług infrastrukturalnych.

Można to uprościć:

```text
Firebase
→ szybkie tworzenie aplikacji

AWS
→ rozbudowana infrastruktura cloud
```
