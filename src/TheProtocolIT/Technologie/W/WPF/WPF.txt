# WPF

## 1. Czym jest WPF?

**WPF (Windows Presentation Foundation)** to framework firmy Microsoft służący do tworzenia **graficznych aplikacji desktopowych dla systemu Windows**.

WPF jest częścią ekosystemu **.NET** i pozwala tworzyć aplikacje z wykorzystaniem:

- C#,
- XAML,
- .NET,
- kontrolek GUI,
- zdarzeń,
- bindingu danych,
- stylów,
- szablonów,
- animacji,
- grafiki 2D/3D.

Najprościej:

> **WPF pozwala tworzyć nowoczesne aplikacje okienkowe Windows w C# z interfejsem definiowanym głównie za pomocą XAML.**

Przykładowa aplikacja:

```text
┌──────────────────────────────────────┐
│  Moja aplikacja                _ □ X │
├──────────────────────────────────────┤
│                                      │
│  Imię:     [________________]        │
│                                      │
│  Email:    [________________]        │
│                                      │
│             [ ZAPISZ ]               │
│                                      │
└──────────────────────────────────────┘
```

## 2. Do czego służy WPF?

WPF jest wykorzystywany do tworzenia aplikacji desktopowych, takich jak:

- systemy biznesowe,
- aplikacje administracyjne,
- programy finansowe,
- systemy magazynowe,
- aplikacje laboratoryjne,
- narzędzia developerskie,
- aplikacje bazodanowe,
- systemy przemysłowe,
- aplikacje wykorzystujące grafikę,
- wewnętrzne systemy firmowe.

Przykład:

```text
WPF
 ↓
Aplikacja desktopowa
 ↓
C#
 ↓
.NET
 ↓
API / Database
```

## 3. WPF a Windows

WPF jest przede wszystkim technologią przeznaczoną dla **Windows**.

Jeżeli tworzysz:

```text
Windows Desktop Application
```

WPF jest jednym z najważniejszych frameworków Microsoftu, które warto znać.

Współczesne WPF może działać na współczesnych wersjach .NET, ale pozostaje technologią zorientowaną na Windows.

## 4. WPF i C#

Najczęściej WPF wykorzystuje:

```text

+
```

C# odpowiada przede wszystkim za:

- logikę,
- obsługę zdarzeń,
- komunikację z API,
- pracę z bazą,

- przetwarzanie danych.

XAML odpowiada przede wszystkim za:

Schemat:

```text
             WPF
              │
       ┌──────┴──────┐
       ↓             ↓
     XAML           C#
       │             │
    UI/Layout      Logic
       │             │
       └──────┬──────┘
              ↓
        Aplikacja GUI
```

## 5. Czym jest XAML?

**XAML (Extensible Application Markup Language)** to język oparty na XML używany do definiowania interfejsu użytkownika.

Przykład:

```xml id="5ecv0s"
<Window
    x:Class="MyApp.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
    Title="Moja aplikacja"
    Height="300"
    Width="500">

    <Button
        Content="Kliknij"
        Width="120"
        Height="40"/>

</Window>
```

Zamiast tworzyć całe GUI programowo w C#, możesz opisać je deklaratywnie w XAML.

## 6. XAML + C#

Typowa aplikacja WPF zawiera:

```text
MainWindow.xaml
MainWindow.xaml.cs
```

### MainWindow.xaml

```xml id="r3k9sh"
<Window
    x:Class="MyApp.MainWindow"
    xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation">

    <Button
        Content="Kliknij"
        Click="Button_Click"/>

</Window>
```

### MainWindow.xaml.cs

```csharp id="7m8j3b"
using System.Windows;

namespace MyApp;

public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    private void Button_Click(object sender, RoutedEventArgs e)
    {
        MessageBox.Show("Hello WPF!");
    }
}
```

XAML definiuje przycisk, a C# reaguje na jego kliknięcie.

## 14. Data Binding

Jedną z **najważniejszych funkcji WPF** jest **Data Binding**.

Binding pozwala połączyć kontrolkę z właściwością obiektu.

Przykład:

```xml id="jygv2j"
<TextBox Text="{Binding UserName}"/>
```

Jeżeli obiekt posiada:

```csharp id="2fd0qp"
public string UserName { get; set; }
```

WPF może powiązać tę właściwość z `TextBox`.

Schemat:

```text
C# Object
   │
   │ Binding
   ↓
TextBox
```

## 15. INotifyPropertyChanged

Jeżeli chcemy, aby UI automatycznie reagowało na zmianę właściwości, często wykorzystujemy:

```csharp id="jz6l0x"
INotifyPropertyChanged
```

Przykład:

```csharp id="d7l7sy"
public class User : INotifyPropertyChanged
{
    private string _name;

    public string Name
    {
        get => _name;
        set
        {
            _name = value;
            PropertyChanged?.Invoke(
                this,
                new PropertyChangedEventArgs(nameof(Name)));
        }
    }

    public event PropertyChangedEventHandler? PropertyChanged;
}
```

Wtedy:

```text
Model
 ↓
PropertyChanged
 ↓
Binding
 ↓
UI
```

## 16. ObservableCollection

do obsługi kolekcji danych.

Przykład:

```csharp id="4e9y3w"
public ObservableCollection<User> Users { get; }
```

```xml id="2h0yl3"

```

Jeżeli dodasz element:

```csharp id="kj0j89"
Users.Add(new User());
```

UI może automatycznie zauważyć zmianę.

## 17. MVVM

Jednym z najważniejszych wzorców projektowych stosowanych w WPF jest:

**MVVM – Model-View-ViewModel**

Schemat:

```text
Model
  │
  ↓
ViewModel
  │
  ↓
View
```

### Model

Reprezentuje dane i domenę.

```csharp id="xqwjw7"
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
}
```

### View

Interfejs użytkownika:

```xml id="y1fp8k"
<TextBox Text="{Binding Name}"/>
```

### ViewModel

Łączy View z logiką aplikacji:

```csharp id="w4j5u7"
public class UserViewModel
{
    public User User { get; set; }

    public ICommand SaveCommand { get; }
}
```

## 18. Dlaczego MVVM jest ważne?

Bez MVVM łatwo stworzyć:

```text
Window
 ├── UI
 ├── Database
 ├── Business Logic
 ├── Validation
 └── API
```

i otrzymać bardzo trudny w utrzymaniu kod.

MVVM pozwala rozdzielić odpowiedzialności:

```text
View
 ↓
ViewModel
 ↓
Service
 ↓
Repository
 ↓
Database
```

Dzięki temu aplikacja jest łatwiejsza do:

- testowania,
- rozwijania,
- refaktoryzacji,
- utrzymywania.

## 25. StaticResource i DynamicResource

W WPF możesz spotkać:

```text

```


`DynamicResource` pozwala na dynamiczne reagowanie na zmianę zasobu.


## 42. WPF vs Windows Forms

Jedno z najważniejszych porównań to:

**WPF vs Windows Forms.**

| WPF | Windows Forms |
|---|---|
| Nowsza architektura | Starsza technologia |
| XAML | Głównie C# Designer |
| Data Binding | Data Binding |
| MVVM | Częściej code-behind |
| Styles | Mniej rozbudowane |
| Templates | Ograniczone |
| Animacje | Lepsze wsparcie |
| Nowoczesne UI | Bardziej klasyczne UI |
| .NET | .NET |

Windows Forms jest nadal używany, szczególnie w starszych aplikacjach.

WPF jest zazwyczaj lepszym wyborem, gdy tworzysz nową aplikację wymagającą bardziej rozbudowanego UI.

## 43. WPF vs WinUI

**WinUI** jest nowszym podejściem Microsoftu do tworzenia aplikacji Windows.

W uproszczeniu:

```text
WPF
 ↓
dojrzała technologia desktopowa
```

```text
WinUI
 ↓
nowszy model aplikacji Windows
```

WPF ma jednak ogromny ekosystem istniejących aplikacji i nadal jest ważną technologią w świecie .NET.

## 44. WPF vs .NET MAUI

**.NET MAUI** jest nastawione na aplikacje wieloplatformowe.

| WPF | .NET MAUI |
|---|---|
| Windows | Windows |
| Windows | Android |
| Windows | iOS |
| Windows | macOS |
| Bardzo dojrzałe | Wieloplatformowe |
| XAML | XAML |
| Desktop Windows | Mobile + Desktop |

Jeżeli potrzebujesz wyłącznie Windows:

```text
WPF
```

może być bardzo dobrym wyborem.

warto rozważyć:

## 45. WPF vs Electron

Electron pozwala tworzyć aplikacje desktopowe przy użyciu technologii webowych.

```text
Electron
=
HTML
+
CSS
+
JavaScript
```

WPF:

```text
WPF
=
C#
+
XAML
+
.NET
```

Electron jest dobry dla zespołów webowych, natomiast WPF jest naturalnym wyborem dla ekosystemu .NET/Windows.

## 46. WPF i Dependency Injection

WPF może korzystać z Dependency Injection.

Przykładowa architektura:

```text
DI Container
   │
   ├── UserService
   ├── ApiClient
   ├── Repository
   └── ViewModel
```

Dzięki temu zależności mogą być wstrzykiwane zamiast tworzone bezpośrednio w klasach.

Jest to szczególnie przydatne w większych projektach.

Dzięki temu część logiki można testować niezależnie od GUI.

## 50. Wady WPF

Do wad można zaliczyć:

- aplikacje są przede wszystkim przeznaczone dla Windows,
- XAML ma własną składnię i wymaga nauki,

- duże projekty mogą mieć skomplikowane bindingi,
- technologia jest starsza od części nowszych rozwiązań Microsoftu,
- wymaga znajomości zarówno C#, jak i XAML.
