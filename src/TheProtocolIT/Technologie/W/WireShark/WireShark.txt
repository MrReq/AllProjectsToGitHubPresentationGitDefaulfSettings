# Wireshark

## 1. Czym jest Wireshark?

**Wireshark** to darmowy i otwartoźródłowy **analizator ruchu sieciowego**.

Pozwala przechwytywać oraz analizować pakiety przesyłane przez sieć.

Możesz dzięki niemu zobaczyć między innymi:

- jakie urządzenia komunikują się ze sobą,
- jakie protokoły są używane,
- jakie adresy IP biorą udział w komunikacji,
- jakie porty są wykorzystywane,
- jak wygląda komunikacja TCP,
- jakie zapytania DNS są wykonywane,
- jakie pakiety HTTP są przesyłane,
- dlaczego połączenie nie działa,
- gdzie występują opóźnienia,
- czy występują retransmisje lub błędy.

Najprościej:

> **Wireshark pozwala zajrzeć do ruchu sieciowego i analizować, co naprawdę dzieje się pomiędzy urządzeniami.**

## 2. Do czego służy Wireshark?

Wireshark jest wykorzystywany przede wszystkim do:

- diagnostyki sieci,
- debugowania aplikacji sieciowych,
- analizy protokołów,
- nauki sieci komputerowych,
- wykrywania problemów z TCP/IP,
- analizy DNS,
- analizy HTTP/HTTPS,
- analizy połączeń między serwerami,
- monitorowania ruchu,
- analizy problemów z wydajnością,
- bezpieczeństwa sieciowego,
- analizy incydentów.

Przykładowo aplikacja nie może połączyć się z serwerem:

```text
Aplikacja
   ↓
Internet
   ↓
Serwer
```

Wireshark może pomóc ustalić:

```text
Czy DNS działa?
      ↓
Czy klient wysyła pakiety?
      ↓
Czy serwer odpowiada?
      ↓
Czy TCP zostało zestawione?
      ↓
Czy występują retransmisje?
      ↓
Czy połączenie jest zamykane?
```

## 3. Czym jest pakiet sieciowy?

Podczas komunikacji dane są dzielone na mniejsze fragmenty.

Przykładowo:

```text
Aplikacja
    ↓
Dane
    ↓
TCP
    ↓
IP
    ↓
Ethernet / Wi-Fi
    ↓
Sieć
```

Wireshark pozwala analizować poszczególne elementy tej komunikacji.

Przykładowy pakiet może zawierać:

```text
Ethernet
   ↓
IP
   ↓
TCP
   ↓
HTTP
   ↓
Application Data
```

## 4. Jak działa Wireshark?

Wireshark przechwytuje pakiety z interfejsu sieciowego.

Schemat:

```text
Internet / LAN
      ↓
Karta sieciowa
      ↓
Wireshark
      ↓
Przechwytywanie pakietów
      ↓
Analiza
```

Możesz wybrać konkretny interfejs:

```text
Wi-Fi
Ethernet
Loopback
VPN
Virtual Adapter
```

Następnie Wireshark zaczyna obserwować ruch przechodzący przez wybrany interfejs.

## 5. Interfejs sieciowy

Komputer może mieć wiele interfejsów:

```text
Wi-Fi
Ethernet
VPN
VirtualBox
VMware
Docker
WSL
Loopback
```

Wireshark może przechwytywać ruch z wybranego interfejsu.

Na przykład jeśli korzystasz z Wi-Fi:

```text
Wi-Fi
192.168.1.25
      ↓
Wireshark
      ↓
pakiety
```

Jeśli wybierzesz niewłaściwy interfejs, możesz nie zobaczyć interesującego Cię ruchu.

## 6. Packet Capture

Przechwytywanie ruchu nazywa się **packet capture**.

Wireshark może zapisać przechwycony ruch do pliku:

```text
.pcap
```

lub:

```text
.pcapng
```

Przykład:

```text
network-analysis.pcapng
```

Taki plik można później otworzyć i przeanalizować.

## 7. Główne okno Wiresharka

Po rozpoczęciu przechwytywania zobaczysz listę pakietów.

Typowo znajdują się tam kolumny:

| Kolumna | Znaczenie |
|---|---|
| No. | Numer pakietu |
| Time | Czas |
| Source | Źródło |
| Destination | Cel |
| Protocol | Protokół |
| Length | Długość |
| Info | Informacje o pakiecie |

Przykład:

```text
No.   Source          Destination      Protocol   Length   Info
1     192.168.1.10    8.8.8.8          DNS        74       Standard query
2     8.8.8.8         192.168.1.10     DNS        90       Standard query response
3     192.168.1.10    142.250.x.x      TCP        66       SYN
```

## 9. Ethernet

Ethernet odpowiada za komunikację na poziomie sieci lokalnej.

Wireshark może pokazywać między innymi:

```text

Destination MAC
EtherType
Frame information
```

Przykład:

```text
Source MAC:
AA:BB:CC:11:22:33

Destination MAC:
FF:EE:DD:44:55:66
```

MAC Address identyfikuje interfejs sieciowy w warstwie łącza danych.

## 10. IP

Możesz zobaczyć:

```text

Protocol

```

Przykład:

```text
Source:

Destination:
142.250.185.14
```

Możesz dzięki temu sprawdzić, z jakim adresem komunikuje się komputer.

## 11. TCP

**TCP** jest jednym z najważniejszych protokołów, które analizuje się w Wiresharku.

Możesz zobaczyć między innymi:

- SYN,
- SYN/ACK,
- ACK,
- FIN,
- RST,
- Sequence Number,
- Acknowledgment Number,
- Window Size,
- retransmisje.

## 12. Three-Way Handshake

Jednym z najważniejszych przykładów jest zestawianie połączenia TCP.

Wygląda ono tak:

```text
Klient                         Serwer
   │                              │
   │ -------- SYN --------------> │
   │                              │
   │ <------ SYN + ACK ---------- │
   │                              │
   │ -------- ACK --------------> │
   │                              │
   │       Połączenie TCP         │
```

Wireshark pozwala zobaczyć wszystkie trzy pakiety.

To świetny sposób na zrozumienie TCP.

## 13. SYN

Pierwszy etap:

```text
Client → Server

SYN
```

Klient mówi:

> Chcę rozpocząć połączenie TCP.

Następnie:

```text
Server → Client

SYN + ACK
```

Serwer odpowiada.

Na końcu:

```text
Client → Server

ACK
```

Połączenie zostaje zestawione.

## 14. TCP Retransmission

Jednym z bardzo przydatnych zastosowań Wiresharka jest wykrywanie **retransmisji TCP**.

Jeżeli pakiet nie dotrze do odbiorcy, TCP może wysłać go ponownie.

Wireshark może oznaczyć taki pakiet jako:

```text
[TCP Retransmission]
```

Może to wskazywać na:

- utratę pakietów,
- problemy z siecią,
- przeciążenie,
- problemy z Wi-Fi,
- problemy z serwerem lub infrastrukturą.

## 15. UDP

Wireshark pozwala również analizować UDP.

UDP jest prostszy od TCP.

```text
TCP
Connection-oriented
Reliable
Ordering
Retransmission
```

Natomiast:

```text
UDP
Connectionless
No built-in reliability
Low overhead
```

UDP jest często wykorzystywany między innymi przez:

- DNS,
- DHCP,
- streaming,
- VoIP,
- gry sieciowe.

## 19. HTTPS

HTTPS wykorzystuje szyfrowanie TLS.

Schemat:

```text
HTTP
 ↓
TLS
 ↓
TCP
 ↓
IP
```

W typowej sytuacji Wireshark może zobaczyć informacje dotyczące połączenia TLS, ale **nie zobaczy po prostu jawnej treści HTTP**, ponieważ jest ona szyfrowana.

Możesz jednak analizować między innymi:

- handshake TLS,
- certyfikat,
- wersję TLS,
- parametry połączenia,
- adresy IP,
- porty,
- czas komunikacji,
- rozmiary pakietów.

   │
   │ ClientHello

   │ ServerHello

## 22. Capture Filter

**Capture Filter** określa, jaki ruch ma być przechwytywany.

Przykład:

```text
port 443
```

Oznacza:

> przechwytuj ruch związany z portem 443.

Inne przykłady:

```text
host 192.168.1.10
```

```text
tcp
```

```text
udp
```

```text
port 53
```

## 23. Display Filter

Bardzo ważną funkcją Wiresharka jest **Display Filter**.

Pozwala filtrować już przechwycone pakiety.

Przykłady:

```text
http
```

```text
dns
```

```text
tcp
```

```text
udp
```

```text
icmp
```

```text
ip.addr == 192.168.1.10
```

```text
tcp.port == 443
```

```text
dns.qry.name == "example.com"
```

## 24. Capture Filter vs Display Filter

To bardzo ważne rozróżnienie.

| Capture Filter | Display Filter |
|---|---|
| Filtruje podczas przechwytywania | Filtruje po przechwyceniu |
| Ogranicza ilość zbieranych danych | Ogranicza to, co oglądasz |
| Może zmniejszyć rozmiar capture | Nie usuwa pakietów |
| Składnia BPF | Składnia Wiresharka |

Przykład:

```text
Capture Filter:
port 443
```

a później:

```text
Display Filter:
ip.addr == 10.0.0.5
```

## 25. Follow TCP Stream

Jedna z bardzo przydatnych funkcji to:

Pozwala zobaczyć komunikację należącą do konkretnego połączenia TCP w bardziej uporządkowanej formie.

Schemat:

```text
Packet 1
Packet 2
Packet 3
Packet 4
Packet 5
      ↓
TCP Stream
      ↓
cała rozmowa klient ↔ serwer
```

Jest to szczególnie przydatne przy analizie protokołów tekstowych.

## 28. Expert Information

Wireshark posiada również funkcję **Expert Information**.

Może wskazywać potencjalne problemy związane z analizowanym ruchem.

Przykładowo:

```text
TCP Retransmission
TCP Out-of-Order
TCP Duplicate ACK
Connection Reset
Malformed Packet
```

Nie oznacza to automatycznie, że sieć jest uszkodzona.

Jest to wskazówka, którą trzeba odpowiednio zinterpretować.

## 29. PCAP

Jednym z najważniejszych formatów używanych przez Wiresharka jest:

```text
PCAP
```

oraz:

```text
PCAPNG
```

Możesz:

```text
przechwycić ruch
      ↓
zapisać PCAPNG
      ↓
przesłać plik
      ↓
otworzyć na innym komputerze
      ↓
przeanalizować
```

Jest to bardzo przydatne podczas pracy zespołowej.

## 30. Wireshark a cyberbezpieczeństwo

Wireshark jest również wykorzystywany w bezpieczeństwie.

Można analizować:

- podejrzane połączenia,
- nietypowe DNS,
- skany sieci,
- komunikację malware,
- anomalie TCP,
- nieoczekiwane adresy IP,
- nietypowe protokoły.

Przykład:

```text
Normalny ruch:

PC → DNS → znany serwer

Podejrzany ruch:

PC → DNS → nieznana domena
PC → IP → nietypowy serwer
PC → wiele portów
```

Wireshark może pomóc zauważyć takie zachowanie.

## 31. Wireshark a Nmap

| Wireshark | Nmap |

Można używać ich razem:

```text
Nmap
 ↓

 ↓

```

## 37. Przykład: dlaczego aplikacja nie łączy się z PostgreSQL?

Załóżmy:

```text
Spring Boot
    ↓
PostgreSQL
    ↓
Port 5432
```

A aplikacja zwraca:

```text
Connection refused
```

Możesz sprawdzić:

```text
1. Czy DNS działa?
2. Czy klient wysyła SYN?
3. Czy serwer odpowiada SYN/ACK?
4. Czy połączenie zostaje odrzucone?
5. Czy występuje RST?
6. Czy serwer jest dostępny?
```

Przykładowo:

```text
Client
   │
   │ SYN
   ↓
PostgreSQL
   │
   │ RST
   ↓
Client
```

To może wskazywać, że połączenie jest odrzucane.

## 42. Wady Wiresharka

Należy pamiętać, że:

- ogromna liczba pakietów może być trudna do analizy,
- wymaga znajomości sieci,
- początkujący może poczuć się przytłoczony,
- HTTPS ogranicza widoczność treści,
- przechwytywanie ruchu może mieć konsekwencje związane z prywatnością,
- nie każdy problem aplikacji jest problemem sieciowym.

## 47. Wireshark w jednym przykładzie

Załóżmy, że aplikacja:

```text
Spring Boot
    ↓
http://api.example.com
```

nie działa.

Możesz przeanalizować:

```text
1. DNS
   ↓
   Czy api.example.com jest rozwiązywane?

2. TCP
   ↓
   Czy powstaje połączenie?

3. TLS
   ↓
   Czy handshake się udaje?

4. HTTP
   ↓
   Czy request jest wysyłany?

5. Response
   ↓
   Czy serwer odpowiada?

6. TCP
   ↓
   Czy występują retransmisje?
```

W ten sposób Wireshark pozwala przejść od:

**„Aplikacja nie działa”**

do bardziej konkretnego:

**„DNS działa, TCP działa, ale połączenie TLS jest zrywane.”**

To właśnie jest jedna z największych wartości Wiresharka.

## 49. Wireshark – najważniejsza rzecz do zapamiętania

**Wireshark to narzędzie do przechwytywania i szczegółowej analizy ruchu sieciowego na poziomie pakietów.**

Najważniejszy schemat:

```text
Aplikacja
   ↓
HTTP / DNS / TLS
   ↓
TCP / UDP
   ↓
IP
   ↓
Ethernet / Wi-Fi
   ↓
Sieć
```

Wireshark pozwala obserwować tę komunikację i dzięki temu diagnozować problemy z **siecią, serwerami, API, Dockerem, Kubernetesem, aplikacjami oraz bezpieczeństwem**.

**Najważniejsze zdanie do zapamiętania: Wireshark pozwala zobaczyć i przeanalizować, co naprawdę dzieje się z pakietami podczas komunikacji sieciowej.**
