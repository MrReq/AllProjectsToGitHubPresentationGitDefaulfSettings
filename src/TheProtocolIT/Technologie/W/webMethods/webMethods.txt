# webMethods

## 1. Czym jest webMethods?

**webMethods** to platforma firmy **Software AG** przeznaczona do **integracji systemów, aplikacji, danych i usług**.

Jej głównym zadaniem jest umożliwienie komunikacji pomiędzy różnymi systemami przedsiębiorstwa.

Można ją traktować jako **platformę integracyjną klasy enterprise**, która pozwala łączyć ze sobą:

- aplikacje,
- bazy danych,
- API,
- systemy ERP,
- systemy CRM,
- usługi webowe,
- aplikacje chmurowe,
- systemy partnerskie,
- pliki i komunikaty.

Przykładowo firma może posiadać:

```text
CRM
 |
 +---- ERP
 |
 +---- Baza danych
 |
 +---- System płatności
 |
 +---- Sklep internetowy
 |
 +---- System magazynowy
```

webMethods może pełnić rolę warstwy integracyjnej pomiędzy tymi systemami.

## 2. Do czego służy webMethods?

Głównym zastosowaniem webMethods jest **Enterprise Application Integration (EAI)** oraz **Application Integration**.

Przykładowo:

```text
Sklep internetowy
       |
       ↓
   webMethods
       |
   +---+---+
   |       |
   ↓       ↓
  ERP    CRM
```

Klient składa zamówienie w sklepie internetowym.

webMethods może:

1. odebrać zamówienie,
2. przekształcić dane,
3. wysłać je do ERP,
4. zaktualizować CRM,
5. przekazać informację do magazynu,
6. obsłużyć odpowiedź,
7. zarejestrować błąd, jeśli któryś system nie odpowie.

## 3. webMethods jako middleware

webMethods jest przykładem **middleware**.

Middleware to warstwa znajdująca się pomiędzy różnymi aplikacjami.

```text
       Aplikacja A
            |
            ↓
       Middleware
       webMethods
            |
            ↓
       Aplikacja B
```

Dzięki temu poszczególne systemy nie muszą bezpośrednio znać szczegółów implementacji innych systemów.

## 4. Problem, który rozwiązuje webMethods

Wyobraźmy sobie przedsiębiorstwo posiadające:

```text
Java Application
.NET Application
SAP
Oracle
SQL Server
REST API
SOAP API
FTP
```

Bez platformy integracyjnej moglibyśmy mieć wiele bezpośrednich połączeń:

```text
Java ↔ SAP
Java ↔ Oracle
Java ↔ REST
.NET ↔ SAP
.NET ↔ Oracle
.NET ↔ FTP
...
```

Liczba integracji może bardzo szybko wzrosnąć.

webMethods pozwala stworzyć centralną warstwę integracyjną:

```text
             SAP
              |
Java ---- webMethods ---- REST API
              |
.NET ---------+
              |
          SQL Server
```

## 5. Integration Server

Jednym z najważniejszych komponentów webMethods jest **webMethods Integration Server**.

Jest to centralny element platformy odpowiedzialny za wykonywanie procesów integracyjnych.

Można go przedstawić:

```text
System A
   |
   ↓
Integration Server
   |
   ↓
System B
```

Integration Server może:

- odbierać komunikaty,
- przetwarzać dane,
- wywoływać usługi,
- transformować dane,
- komunikować się z bazami danych,
- obsługiwać API,
- wykonywać logikę integracyjną.

## 6. Services

W webMethods bardzo ważnym pojęciem są **services**.

Service reprezentuje określoną operację wykonywaną przez platformę.

Przykładowo:

```text
createCustomer
getCustomer
updateCustomer
processOrder
sendInvoice
```

Service może być wywoływany przez inne usługi lub systemy.

## 7. Flow Services

Jednym z charakterystycznych mechanizmów webMethods są **Flow Services**.

Flow Service pozwala definiować proces integracyjny poprzez kolejne kroki.

Przykładowo:

```text
Receive Order
      ↓
Validate Order
      ↓
Transform Data
      ↓
Send to ERP
      ↓
Update CRM
      ↓
Return Response
```

Zamiast pisać całą logikę integracyjną od podstaw, można ją budować z gotowych operacji.

## 8. Designer

Do projektowania usług w webMethods wykorzystywane są narzędzia programistyczne, między innymi **webMethods Designer**.

Pozwala on tworzyć i zarządzać:

- usługami,
- flow services,
- mapowaniami,
- schematami,
- strukturami danych,
- integracjami.

Można wizualizować przepływ:

```text
START
  ↓
MAP
  ↓
CALL SERVICE
  ↓
BRANCH
  ↓
END
```

## 9. Data Mapping

Systemy często wykorzystują różne formaty danych.

Na przykład system A może zwracać:

```json
{
  "firstName": "John",
  "lastName": "Smith"
}
```

a system B oczekiwać:

```xml
<Customer>
    <Name>John Smith</Name>
</Customer>
```

webMethods może wykonać transformację:

```text
JSON
 ↓
Mapping
 ↓
XML
```

Jest to jedna z najważniejszych funkcji platform integracyjnych.

## 10. Transformation

webMethods umożliwia transformowanie danych pomiędzy różnymi strukturami.

Przykładowo:

```text
Customer
{
    firstName
    lastName
    email
}
```

może zostać przekształcony do:

```text
Client
{
    name
    contact
}
```

Platforma może więc działać jako **translator pomiędzy systemami**.

## 11. Adapters

Systemy przedsiębiorstwa wykorzystują wiele różnych technologii.

webMethods wykorzystuje **adaptery**, które umożliwiają komunikację z określonymi systemami.

Przykładowe zastosowania:

```text
Database Adapter
SAP Adapter
JDBC
HTTP
JMS
FTP
```

Dzięki temu platforma może integrować systemy wykorzystujące różne technologie.

## 15. API Gateway

Ekosystem webMethods obejmuje również rozwiązania związane z zarządzaniem API.

**API Gateway** może znajdować się pomiędzy klientami a usługami backendowymi.

```text

   ↓

   |
   +---- Service A
   |
   +---- Service B
   |
   +---- Service C
```

API Gateway może realizować między innymi:

- routing,
- bezpieczeństwo,
- autoryzację,
- monitoring,
- kontrolę dostępu,
- zarządzanie API.

```text

     |
     ↓
Another Application
```

Jest to szczególnie przydatne w architekturach rozproszonych.

Przykładowo:

## 25. EDI

W integracji B2B często wykorzystywany jest **EDI (Electronic Data Interchange)**.

EDI umożliwia elektroniczną wymianę ustandaryzowanych dokumentów pomiędzy firmami.

Przykładowo:

```text
Order
Invoice
Shipping Notice
```

webMethods może być elementem infrastruktury obsługującej takie procesy.

## 28. webMethods a ESB

Jednym z ważnych pojęć związanych z webMethods jest **ESB – Enterprise Service Bus**.

ESB jest architekturą umożliwiającą komunikację pomiędzy wieloma usługami i systemami.

Można ją przedstawić:

```text
System A
    |
System B → ESB ← System C
    |
System D
```

webMethods było historycznie jednym z popularnych rozwiązań wykorzystywanych jako platforma ESB.

- skomplikowany,
- kosztowny,
- wymagający specjalistycznej wiedzy,
- trudniejszy do wdrożenia niż proste rozwiązanie REST,
- przesadnie rozbudowany dla małej aplikacji.

Dla małego projektu:

```text

   ↓
REST API
   ↓
PostgreSQL
```

webMethods prawdopodobnie byłby niepotrzebnym narzutem.

Natomiast dla dużej organizacji:

```text

ERP

Legacy

```

platforma integracyjna może mieć ogromny sens.

## 36. Najważniejsze pojęcia

Jeżeli chcesz zapamiętać webMethods, przede wszystkim zapamiętaj:

**webMethods** – platforma enterprise do integracji systemów, aplikacji, danych i usług.

**Integration Server** – centralny komponent wykonujący procesy integracyjne.

**Flow Service** – usługa definiująca przepływ operacji integracyjnych.

**Designer** – narzędzie do projektowania usług i integracji.

**Adapter** – mechanizm umożliwiający komunikację z określonym systemem lub technologią.

**API Gateway** – warstwa pośrednicząca w obsłudze i zarządzaniu API.

**ESB** – Enterprise Service Bus, architektura integracji wielu systemów.

**B2B** – integracja pomiędzy przedsiębiorstwami.

**EDI** – elektroniczna wymiana ustandaryzowanych dokumentów.

**Data Mapping** – mapowanie danych pomiędzy różnymi strukturami.

**Transformation** – przekształcanie danych z jednego formatu do drugiego.
