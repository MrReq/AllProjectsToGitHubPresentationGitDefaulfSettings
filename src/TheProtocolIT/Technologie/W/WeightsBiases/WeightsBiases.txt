# Weights & Biases (W&B)

## 1. Czym jest Weights & Biases?

**Weights & Biases (W&B)**, często zapisywane jako **wandb**, to platforma przeznaczona do **śledzenia, eksperymentowania, wizualizacji i zarządzania projektami związanymi z machine learningiem i sztuczną inteligencją**.

W&B pomaga zespołom ML rejestrować informacje o przeprowadzanych eksperymentach.

Można dzięki niemu śledzić między innymi:

- parametry modeli,
- hiperparametry,
- metryki,
- funkcje straty,
- dokładność,
- wykresy,
- eksperymenty,
- wersje modeli,
- datasety,
- artefakty,
- wyniki treningu.

Najprościej:

**Weights & Biases pozwala odpowiedzieć na pytanie: „Co dokładnie zrobiłem podczas trenowania tego modelu i dlaczego ten eksperyment był lepszy od poprzedniego?”**

## 2. Jaki problem rozwiązuje W&B?

Załóżmy, że trenujesz model AI.

Eksperyment 1:

```text
learning_rate = 0.001
epochs = 10
batch_size = 32
accuracy = 87%
```

Eksperyment 2:

```text
learning_rate = 0.0005
epochs = 20
batch_size = 64
accuracy = 91%
```

Po wykonaniu 50 eksperymentów bardzo trudno pamiętać, która konfiguracja dała najlepszy wynik.

W&B pozwala automatycznie zapisywać takie informacje:

```text
Experiment 1 → 87%
Experiment 2 → 91%
Experiment 3 → 89%
Experiment 4 → 94%
...
```

Dzięki temu możemy porównywać eksperymenty.

## 3. Machine Learning Experiment Tracking

Jedną z najważniejszych funkcji W&B jest **experiment tracking**.

Podczas treningu modelu możemy rejestrować:

```text

   ↓
W&B
   ↓
Metrics
Parameters
Graphs
Artifacts
```

Przykładowe metryki:

```text
loss
accuracy
precision
recall
F1-score
learning rate
```

## 4. Run

Jednym z podstawowych pojęć w W&B jest **Run**.

**Run** reprezentuje pojedyncze uruchomienie eksperymentu.

Przykładowo:

```text
Run 1
learning_rate = 0.001
epochs = 10
accuracy = 87%

Run 2
learning_rate = 0.0005
epochs = 20
accuracy = 91%
```

Każdy Run może przechowywać własne parametry, metryki i inne informacje.

## 5. Project

W&B pozwala organizować eksperymenty w ramach **Projects**.

Przykładowo:

```text
Project: Image Classification
    |
    +-- Run 1
    +-- Run 2
    +-- Run 3
    +-- Run 4
```

W jednym projekcie możemy przechowywać wszystkie eksperymenty dotyczące określonego modelu lub problemu.

## 6. Sweep

**Sweep** służy do automatycznego testowania różnych konfiguracji hiperparametrów.

Przykładowo chcemy sprawdzić:

```text
learning_rate:
0.1
0.01
0.001
0.0001
```

oraz:

```text
batch_size:
16
32
64
```

Wtedy mamy wiele kombinacji:

```text
0.1 × 16
0.1 × 32
0.1 × 64
0.01 × 16
...
```

W&B Sweeps może pomagać w automatyzacji takiego procesu.

## 36. Prosty przykład

Przykładowy kod Python:

```python
import wandb

wandb.init(
    project="my-ml-project",
    config={
        "learning_rate": 0.001,
        "epochs": 10,
        "batch_size": 32
    }
)

for epoch in range(10):
    loss = 1 / (epoch + 1)

    wandb.log({
        "epoch": epoch,
        "loss": loss
    })

wandb.finish()
```

Tutaj:

```text
wandb.init()
```

rozpoczyna eksperyment.

```text
config
```

przechowuje parametry eksperymentu.

```text
wandb.log()
```

zapisuje metryki.

```text
wandb.finish()
```

kończy Run.

## 39. Wady W&B

W&B ma również pewne ograniczenia.

Jest dodatkowym narzędziem, którego trzeba nauczyć się i zintegrować z projektem.

W przypadku bardzo prostych eksperymentów może być niepotrzebnie rozbudowany.

W projektach wymagających pełnej kontroli nad infrastrukturą trzeba również dokładnie zaplanować sposób przechowywania danych i artefaktów.

## 41. Weights & Biases – najważniejsze pojęcia

**Weights & Biases (W&B)** – platforma do śledzenia i zarządzania eksperymentami machine learning.

**wandb** – nazwa biblioteki Python oraz często używany skrót platformy.

**Run** – pojedyncze uruchomienie eksperymentu.

**Project** – zbiór powiązanych eksperymentów.

**Config** – parametry i hiperparametry eksperymentu.

**Metric** – wartość opisująca wynik modelu, np. loss lub accuracy.

**Sweep** – automatyczne testowanie różnych konfiguracji hiperparametrów.

**Artifact** – wersjonowany zasób, np. dataset lub model.

**Dashboard** – wizualny panel przedstawiający wyniki.

**Table** – narzędzie do analizowania danych i wyników modeli.

**Model Registry** – zarządzanie modelami i ich wersjami.

**Experiment Tracking** – rejestrowanie przebiegu eksperymentów.

**MLOps** – praktyki związane z zarządzaniem cyklem życia modeli ML.
